# daily-dots PRD

> 상태: 확정 · 버전: 3 · 갱신: 2026-09-27

앱 이름은 아직 정하지 않았다. `daily-dots` 는 임시 폴더 이름이다. 원본 아이디어는 `~/Downloads/PRODUCT.md` 에 있다.

## 1. 문제

할 일이 적은 날, 약속이 취소된 날, 만날 친구가 없는 날을 보낸 사람은 하루를 돌아볼 때 "한 게 없다"고 느끼기 쉽다. 하루를 기록 개수나 연속 기록 일수로 재면 기록이 적은 날은 실패처럼 보인다. 기록을 남기라고 재촉하는 알림은 그 부담을 더 키운다.

## 2. 목적

하루 안의 순간을 점으로 남기고, 하루·한 달·일 년을 돌아봤을 때 "괜찮았다"고 느끼게 한다. 점이 적은 날도 빈칸이 아니라 조용한 하루로 보여 준다.

첫 버전은 익숙한 Next.js로 핵심 화면을 먼저 만들어 시험하는 웹 앱이다. 사람들이 계속 쓰고 싶어 하는지 확인한 뒤 모바일 앱을 만들지 정한다. 결과가 좋으면 그때 Flutter나 네이티브 앱 가운데 하나를 고른다.

기능과 화면을 정할 때는 아래 원칙을 가장 먼저 따른다.

1. **귀찮게 하지 않는다.** 재촉, 질문, 죄책감을 주는 화면을 만들지 않는다.
2. **조용히 늘 관리한다.** 사용자가 아무것도 하지 않아도 하루는 기록되고 쌓인다.
3. **평가하지 않는다.** 기록 개수, 비교, 연속 기록 같은 수치로 하루를 판단하지 않는다.
4. **누군지 묻지 않는다.** 계정과 프로필이 없다.
5. **미니멀.** 화면의 주인공은 점과 여백이다.

## 3. 사용자

| 사용자(역할) | 하는 일 |
| --- | --- |
| 기록하는 사람 | 휴대폰 브라우저로 오늘 화면을 열고, 원할 때 시작 점과 순간 기록을 남기고, 하루 타임라인과 월간 아카이브를 본다 |

역할은 하나다. 계정이 없으므로 로그인도 없다.

## 4. 핵심 흐름 (첫 버전)

1. 휴대폰 브라우저에서 앱 주소를 열면 바로 오늘 화면이 보인다. 앱이 먼저 알림을 보내거나 화면을 띄우지 않는다.
2. 원하면 "오늘 시작"을 눌러 그 시각에 시작 점을 남긴다. 누르지 않아도 된다.
3. 낮에 사진이나 한 줄로 순간을 남기면 타임라인에 점이 생긴다. 사진에 촬영 시각이 있으면 그 시각 자리에 놓인다.
4. 하루 타임라인에는 점만 보인다. 점을 누르면 사진과 한 줄이 펼쳐진다.
5. 월간 아카이브에서 한 달 동안 찍힌 점들이 만든 모양을 본다.

아무것도 하지 않은 날에도 그 날짜의 **하루 점**이 하나 남는다. 그래서 처음 연 날부터 모든 하루에 점이 최소 하나 있다.

원본 아이디어의 하루 흐름 가운데 알람, 비서(내일 일정 등록, 아침 브리핑), 취침 마무리 문장은 다음 버전에서 다룬다.

## 5. 범위

### 이번에 만든다

- **오늘 화면과 하루 타임라인** — 주소를 열면 곧바로 오늘이 보이고, 기록을 요구하지 않는다.
- **"오늘 시작" 점** — 알람 없이도 원하면 하루의 시작을 직접 남긴다.
- **하루 점** — 기록이 없는 날에도 날짜마다 점 하나를 남겨 "모든 하루에 최소 한 점"을 지킨다.
- **사진과 한 줄 기록, 수정·삭제** — 낮의 순간을 남기는 기본 동작이다.
- **촬영 시각으로 점 배치** — 나중에 사진을 골라도 실제 시각 자리에 점이 놓인다.
- **점 상세 펼치기** — 화면에는 점만 두고, 누를 때만 내용을 보여 준다.
- **점 모양으로 카테고리 구분** — 색을 늘리지 않고 크기·채움·테두리로 구분한다.
- **월간 아카이브** — 개수 없이 점들이 만든 모양으로만 보여 준다.

### 이번에 만들지 않는다

- **홈 화면 위젯** — 웹 앱으로는 iOS 홈 화면 위젯을 만들 수 없다. 모바일 앱을 만들기로 하면 그때 넣는다.
- **알람과 기상 점** — 알람(AlarmKit)은 네이티브 iOS 기능이라 웹에서 쓸 수 없다. 모바일 앱에서 원하는 사람만 쓰는 선택 기능으로 다룬다.
- **캘린더 일정 표시** — 일정 기능은 비서와 함께 다룬다.
- **비서(내일 일정 등록, 아침 브리핑, 일정 전 푸시)** — 일정 등록을 강제하면 "귀찮게 하지 않는다"와 부딪힐 수 있다. 개인 기록이 먼저 쓰이는지 확인한 뒤 사용성 검증으로 정한다.
- **취침 마무리 문장** — 원본 흐름에서 내일 일정 등록 다음에 나오는 화면이라 비서와 함께 다룬다.
- **연간 아카이브** — 첫 버전은 월간까지만 만든다.
- **공유(이미지 공유, 익명 공개 피드)** — 공유 없이도 개인 아카이브를 다시 보고 싶은지 먼저 확인한다. 공개 피드에는 게시물 필터와 신고·차단 운영이 함께 필요하다.
- **꾸미기 결제** — 꾸준히 쓰는 사람이 생긴 뒤에 붙인다.
- **배너 광고** — 보류 중이다. 광고 SDK의 기기 식별이 익명 원칙과 부딪힐 수 있다.
- **계정, 서버 저장, 백업 동기화** — 기록은 기기의 브라우저 안에만 저장한다.

## 6. 제약

- **플랫폼:** 휴대폰 브라우저에서 쓰는 웹 앱.
- **스택:** Next.js. 모바일 앱 스택(Flutter 또는 네이티브)은 웹 시험 결과를 본 뒤 정한다(미결 7).
- **저장:** 기록은 그 기기의 브라우저 안에만 저장하고 서버로 보내지 않는다. 브라우저 데이터를 지우거나 다른 브라우저·기기로 열면 기록이 보이지 않는다.
- **사진 접근:** 사용자가 고른 사진만 받는다.
- **사용 기록:** 서버에 기록을 모으지 않으므로 "계속 쓰는지"는 테스트 참여자에게 직접 물어 확인한다.
- **기한·비용:** 정하지 않았다(미결 4).

## 7. 성공 기준

첫 버전은 아래가 모두 참일 때 끝난 것으로 본다.

- SPEC의 필수 기능 수용 기준을 모두 통과한 웹 앱이 배포되어, 테스트 참여자에게 주소가 전달됐다.
- 테스트 참여자에게 물을 질문 목록이 준비됐다. 질문에는 다음이 들어간다.
  - 주소를 열었을 때 오늘 화면이 한눈에 이해되는가
  - 기록이 적은 날에도 열고 싶은가
  - 첫 주가 지난 뒤 월간 아카이브를 다시 봤는가
  - 조용한 하루도 괜찮게 느꼈는가
  - 앞으로도 계속 쓰고 싶은가

이 질문의 결과로 모바일 앱을 만들지 정한다. 기록 개수, 연속 기록, 다른 사용자와의 비교는 성공 기준으로 쓰지 않는다. 테스트 결과는 참여자 범위 안에서만 해석하고 전체 시장 수요로 넓히지 않는다.

에이전트가 정했고, 버전 3에서 사용자가 문서 전체를 확정했다.

| 하루 점은 그 브라우저에서 앱을 처음 연 날부터 오늘까지 날짜마다 하나씩 생긴다 | 처음 열기 전 날짜는 앱이 알 수 없다 | F3 |

| "오늘 시작" 점은 오늘에만, 하루에 하나, 누른 시각에 남는다 | 원본의 "실제로 확인하지 않은 시각을 기록하지 않는다" | F2 |
| 사진과 한 줄 가운데 하나만 있어도 저장된다 | 원본 추가 제안의 "사진, 일정, 한 줄 중 편한 것으로 기록을 시작한다" | F4 AC3 |
| 한 줄은 최대 80자다 | 타임라인 상세에서 두세 줄 안에 보인다 | F4 AC4 |
| 고른 사진은 브라우저 저장소에 긴 변 2048px로 줄여 저장한다 | 서버 없이 다시 보여 주려면 사진을 직접 갖고 있어야 한다 | SPEC 데이터 |
| 촬영 날짜가 오늘이 아니면 촬영한 날의 타임라인에 점을 놓는다 | 촬영 시각 배치를 날짜까지 따른다 | F6 AC3 |
| 카테고리 선택은 필수가 아니다. 고르지 않으면 기본 모양이다 | 기록할 때 묻는 것을 줄인다 | F8 AC3 |
| 순간 기록이 없는 날에는 "조용한 하루"라는 문구를 보여 준다 | 원칙 5 | F1 AC3 |
| 월간 아카이브는 날짜마다 한 칸이고, 칸 안에 하루 점과 그날의 점을 시각 위치대로 그린다 | 원본에 "풍경"의 구체적인 모습이 없다 | F9 |
| 기록 삭제는 확인을 한 번 거치고, 지운 기록은 되살릴 수 없다 | 서버와 휴지통이 없다 | F5 AC3 |
